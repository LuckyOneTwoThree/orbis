## 2. 产品目标与成功标准

**MVP 目标一句话：**

> 用户在 Orbis 内完成 5 款游戏的发现、启动与管理，并在鸣潮（L1）与原神（L3）上体验安全的一键增强。

**成功标准（发布门槛 = 00 基石 §12.4 A 组全部通过）：**

1. **广度层**：任意一款已安装游戏，从被发现到启动全程不离开 Orbis
2. **深度层·鸣潮**：一键 120FPS → 游戏更新后失效提示 → 一键回滚，全链路可用
3. **深度层·原神**：风险告知 → 显式确认 → 启用后随启动自动解锁，可用
4. **北极星检验（MVP 切面）**：鸣潮/原神玩家装完 Orbis 后，不再需要单独下载和管理第三方 FPS 工具

## 3. 用户与关键旅程

**目标用户**：Persona A（多二游玩家，00 基石 §3.1），MVP 主场景为主玩鸣潮或原神的 PC 玩家。

**五条关键旅程（J1–J5）**：

| 旅程 | 场景 | 涉及功能 |
|------|------|----------|
| J1 首次使用 | 安装打开 → 自动扫描 → 确认游戏列表 → 进入首页 | A1–A3, D1 |
| J2 日常启动 | 打开 Orbis → 首页看到状态 → 一键启动 → 记录时长 | A4–A6, D1 |
| J3 鸣潮增强（aha） | Dashboard → Enhancement 卡片 → 一键启用 → 透明卡片展示 备份→修改→验证 → 启动游戏 | B1–B5, D4 |
| J4 原神解锁 | 原神 Dashboard → 工具详情（默认关闭）→ 风险告知 → 显式确认 → 启用；此后每次启动自动解锁 | B7, B8, C2, C3 |
| J5 更新后失效 | 游戏版本变化 → 首页徽标 → Dashboard 显示「工具未验证」→ 用户选择：等待验证 / 回滚（鸣潮）/ 普通启动（原神） | A3, B4, B6, C4, E1 |

## 4. 功能需求

### 4.0 通用约定

- **状态模型**：游戏状态与工具状态两维独立（00 基石 §5.7），首页以组合状态标注需处理项
- **修改类操作**：一律展示透明卡片（Action / Backup / Result）
- **数据持久化**：本地优先（SQLite），异常退出不丢已记录数据

### 4.1 A 域 · 游戏管理（广度层，5 款游戏）

#### A1 自动发现

**用户故事**：作为玩家，我希望 Orbis 首次启动时自动找到已安装的 5 款游戏，以便零配置开箱即用。

**验收标准**：

- Given 官方 Launcher 默认路径的标准安装环境，When 首次启动完成扫描，Then 已安装游戏全部以 `Installed` 状态出现在列表
- Given 本机未安装任何一款，When 扫描完成，Then 展示空状态引导（各游戏官方下载入口），而非空白页面

**边界与异常**：

- 多客户端共存（国服/国际服/B 服）：全部列出并标注区服；同款多区服视为多个 GameInstallation（region 字段，00 基石 §7.10）
- 扫描超时或目录权限不足：不阻塞启动，展示部分结果 + 手动添加引导
- 严格只读（L0）：不读取游戏进程内存，不做任何注入

#### A2 手动添加 / 移除

**用户故事**：作为非默认路径安装的玩家，我希望手动指定游戏可执行文件，以便游戏同样被管理。

**验收标准**：

- Given 用户选择了正确的游戏 exe，When 确认添加，Then 游戏进入列表且版本识别正确
- Given 用户移除某游戏，When 确认，Then 仅移除列表条目与管理数据，游戏文件与存档不受影响

**边界与异常**：

- 选择的是官方启动器而非游戏本体：校验文件特征并提示，不静默接受
- 同一路径重复添加：去重提示

#### A3 信息识别

**用户故事**：作为玩家，我希望看到每款游戏的路径、版本与区服，以便确认被管理的对象是正确的。

**验收标准**：

- Given 游戏已安装，When 识别完成，Then 版本号与官方 Launcher 展示一致
- Given 版本无法识别，When 展示，Then 显示 `Unknown`，不猜测、不显示过期缓存值

**边界与异常**：版本识别是 B6 兼容门控与 E1 更新检测的数据基础，识别失败必须显式可见。

#### A4 启动 / 停止

**用户故事**：作为玩家，我希望在 Orbis 内直接启动游戏，以便不再打开多个官方 Launcher。

**验收标准**：

- Given 游戏已安装，When 点击启动，Then 游戏进程被拉起，状态变为 `Running`
- Given 游戏已在运行，When 查看按钮，Then 显示「已在运行」，不重复启动
- Given 用户使用结束进程，When 确认风险提示后，Then 进程被结束并记录日志

**边界与异常**：优先调用官方能力（00 基石 §6.2）；「结束进程」附数据损坏风险提示，非紧急场景引导游戏内退出。

#### A5 运行状态检测

**验收标准**：Given 游戏启动或退出，When 状态变化，Then Orbis 界面在 5 秒内反映新状态；游戏崩溃时状态回落并写日志。

#### A6 游戏时间记录

**用户故事**：作为玩家，我希望看到每款游戏的今日/本周/总计时长，以便了解自己的游玩分布。

**验收标准**：

- Given 游戏从启动到退出运行 N 分钟，When 记录落库，Then 时长误差 ≤ 1 分钟
- Given Orbis 在游戏运行期间被重启，When 重新打开，Then 已记录时长不丢失

**边界与异常**：MVP 口径为「游戏进程存活时长」，UI 明示该口径；前台/后台区分留待 V1.x。

#### A7 启动参数保存

**验收标准**：Given 用户为某游戏配置启动参数，When 下次启动该游戏，Then 参数自动生效且实际作用于游戏进程。

**边界与异常**：参数按游戏独立保存；参数冲突检测不做（P1）。

#### A8 手动配置备份 / 恢复

**用户故事**：作为玩家，我希望对游戏配置做备份和恢复，以便出问题时回到已知良好状态。

**验收标准**：

- Given 点击备份，When 完成，Then 备份列表新增记录（时间戳 + 触发方式 + 文件哈希）
- Given 选择某条历史备份，When 恢复，Then 配置文件内容与该备份一致（哈希校验通过）

**边界与异常**：

- 游戏运行中：阻止备份/恢复（文件占用），提示先退出游戏
- 恢复前自动创建「恢复前备份」，任何恢复操作本身可撤销
- **范围 = Provider 已声明配置路径的游戏**：MVP 确定交付鸣潮（LocalStorage.db 双键 `CustomFrameRate` / `GameQualitySetting.KeyCustomFrameRate`，已声明 P0-B §6；备份 = LocalStorage 整目录快照，含 journal / db2 伴生文件）；其余 4 款在 04 技术设计中逐个核实解锁，未声明前 UI 显示「暂不支持备份」

### 4.2 B 域 · Enhancement（深度层，双标杆）

#### B1 鸣潮 120 FPS 工具（L1 · 配置修改）

**用户故事**：作为鸣潮玩家，我希望一键启用 120FPS 而不手动改 LocalStorage.db，以便安全地提升体验。

**验收标准**：

- Given 鸣潮未运行且工具状态为 `Verified/Compatible`，When 点击启用，Then 备份 → 修改 → 验证 依次执行，游戏内 120FPS 生效
- Given 链路中任一步失败，When 验证不通过，Then 自动回滚并向用户明示结果

**边界与异常**：鸣潮（含启动器）运行中阻止操作；游戏版本 `Unknown` 时被兼容门控拦截（B6）；写入语义与工程红线见 P0-B §6（双键同改 / 上限 120 / 游戏内改画质会锁回 60 的提示义务）。

#### B2 修改前自动备份

**验收标准**：Given 任何配置修改请求，When 执行，Then 必先产生备份记录；无备份不修改（硬性顺序约束）。

#### B3 修改后验证

**验收标准**：Given 修改已写入，When 验证，Then 读回目标项并与期望值比对；不一致即触发 B4。

#### B4 失败自动回滚

**验收标准**：Given 验证失败，When 回滚完成，Then 配置文件与备份哈希一致，结果写入日志并在透明卡片展示。

#### B5 配置历史与一键恢复 UI

**用户故事**：作为玩家，我希望看到配置修改历史并一键恢复到任一节点，以便放心试错。

**验收标准**：Given 存在多条备份，When 打开历史列表，Then 每条可见时间/触发方式/哈希；点击恢复走 A8 相同链路（恢复前备份 → 恢复 → 验证）。

#### B6 兼容性状态提示

**验收标准**：

- Given 鸣潮或原神游戏版本变化，When 用户打开对应 Dashboard，Then Enhancement 卡片显示 `Unknown`（或 `Incompatible`）并给出行动建议（等待验证 / 回滚 / 普通启动）
- Given 工具处于 `Unknown/Incompatible`，When 用户尝试启用，Then 被门控拦截并解释原因

#### B7 原神 120 FPS 解锁工具（L3 · 进程运行时，默认关闭）

**用户故事**：作为原神玩家，我希望在明确知晓风险的前提下启用 120FPS 解锁，以便提升体验且不需要单独管理第三方工具。

**验收标准**：

- Given 工具从未启用（默认关闭），When 用户首次尝试启用，Then 展示完整风险告知（进程级修改说明、理论封号风险与社区历史情况、不承诺绝对安全），必须显式勾选确认后才可启用
- Given 已完成风险确认且工具 `Verified/Compatible`，When 启用并启动原神，Then 解锁器随启动自动加载，游戏内 FPS 上限解除
- Given 原神版本 `Unknown`，When 尝试启用，Then 兼容门控拦截并阻止

**边界与异常**：

- 解锁器自身加载失败：降级为普通启动游戏 + 明示「本次未解锁」，绝不阻塞游戏本体
- 运行时解锁不落盘修改游戏文件，游戏重启即恢复原状——因此价值主张是统一托管 + 兼容门控 + 风险披露，而非备份回滚
- 上游开源项目已核实（2026-09-18，P0-A §1）：选定 34736384/genshin-fps-unlock（MIT，v3.0.4）为集成参考，sefinek fork 为活跃度备选；实现保持可替换
- **发行包分离**：主安装包不含注入器，首次启用时从项目 Releases 独立资产显式下载并校验哈希

#### B8 解锁模式启动编排

**验收标准**：

- Given 原神解锁已启用，When 用户启动原神，Then 解锁器自动挂载，用户无需任何额外手动操作
- Given 用户想本次跳过解锁，When 使用「本次不解锁」开关启动，Then 游戏正常启动且不改变工具启用状态

### 4.3 C 域 · Tool 平台（最小内置，无外部源）

#### C1 Tool Manifest 定义与加载

**验收标准**：

- Given 内置工具以 Manifest 声明（id / name / version / riskLevel / permissions / games / supportedVersions / entry），When 应用加载，Then 无需修改 Core（架构不变量，持续测试保障）
- Given Manifest 缺失或损坏，When 加载，Then 该工具不可见但不影响应用与其他工具

#### C2 Tool 启用 / 禁用 / 详情

**验收标准**：Given 用户打开工具详情，When 页面展示，Then Manifest 全量信息可见（含 License 来源，00 基石 §8.6）；启用/禁用即时生效并写日志。

#### C3 风险分级与权限提示

**验收标准**：

- Given 任一工具，When 展示，Then 明示风险等级（L0–L3）与权限范围（读写哪些路径 / 是否进程操作）
- Given L3 工具，When 状态为未启用，Then 默认关闭；启用必经显式授权流程（B7 为首个实例）

#### C4 兼容性数据（鸣潮 + 原神种子数据）

**验收标准**：

- Given 种子数据（游戏版本 × 工具状态，schema 0.1.0 + 首批 3 条，P0-C）随应用版本本地分发，When 查询某版本组合，Then 按 exact → prefix → Unknown 兜底顺序匹配（P0-C §2.2）返回 `Verified/Compatible/Unknown/Incompatible/Deprecated`
- Given 数据源缺失，When 查询，Then 返回 `Unknown`，不猜测

**边界与异常**：MVP 全量离线可用；社区共建数据回传通道属 Phase 3+（00 基石 §11.2）。

### 4.4 D 域 · 平台与 UI

#### D1 首页

**用户故事**：作为玩家，我希望打开 Orbis 三秒内回答三问——我有哪些游戏 / 能直接启动吗 / 哪些需要处理。

**验收标准**：

- Given 存在任一需处理项（更新可用 / 工具 Unknown / 游戏异常），When 打开首页，Then 不进入二级页面即可看到对应徽标
- Given 全部正常，When 打开首页，Then 最近游玩 + 全部游戏卡片（封面/名称/状态/时长）直接可启动

**内容结构**：最近游玩、全部游戏、需处理提醒（沿用 00 基石 §5.6 三问与 §5.7 UI 草图）。视觉基调深色优先，详细规范见 [03-UI设计文档](03-UI设计文档.md)。

#### D2 Game Dashboard

**验收标准**：Given 用户进入某游戏页，When 页面展示，Then 启动按钮、运行状态、时长、Enhancement 卡片（鸣潮/原神）、备份历史入口（鸣潮）、兼容状态一处可见。

#### D3 统一日志（文件落盘）

**验收标准**：

- Given A/B/C 域任一关键动作发生，When 完成，Then 产生符合 00 基石 §9.1 结构化 schema 的日志行（Source / Category / Level / Message / Context / RelatedGame）；日志仅存本地。

#### D4 操作透明卡片

**验收标准**：Given 任何修改类操作，When 执行，Then 以卡片展示 Action（将做什么）/ Backup（备份了什么）/ Result（结果与变更概要）；鸣潮启用链路全程逐步展示。

#### D5 设置页（P1）

最小范围待定（01 清单 F3：语言 / 主题 / 数据目录等），PRD 不展开。

#### D6 日志查看页（P1）、D7 崩溃恢复（P1）

MVP 阶段日志仅落盘；崩溃后重启恢复运行状态为 P1。

### 4.5 E 域 · 更新

#### E1 更新状态检测

**用户故事**：作为玩家，我希望在 Orbis 内看到哪款游戏有更新，以便决定何时更新（尤其更新会让工具失效）。

**数据源（已拍板，P0-B §4，2026-09-18）**：米哈游系 3 款 = HoYoPlay `getGamePackages` 只读 API（一次调用覆盖三款，国服 base 待 04 实测）；鸣潮 = 官方 CDN `index.json`；终末地 = 无公开 manifest，降级为「本地版本展示 + 官方渠道引导」。不自研下载；探测低频（启动时 + 手动刷新）、只读、用户可关。

**验收标准**：

- Given 本地版本低于已知最新版本（只读探测，不自研下载），When 检测完成，Then 首页与 Dashboard 标注 `UpdateAvailable`
- Given 版本数据源不可达，When 检测，Then 显示 `Unknown`，不误报

#### E2 一键跳转官方 Launcher 更新（P1）

唤起对应官方 Launcher 更新页；MVP 阶段提供「去官方更新」的说明引导作为过渡。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 冷启动 ≤ 3s；标准安装路径扫描 ≤ 3s（SSD 标准环境，不做全盘扫描）；常驻内存目标 < 150MB |
| 可靠性 | 数据本地持久化；异常退出不丢已记录数据；工具失败不影响 Launcher 主流程 |
| 安全 | L0–L3 风险规则全量执行；L3 默认关闭；不承诺「绝对不封号」（00 基石 §8.11） |
| 兼容性 | Windows 10 19041+ / Windows 11 x64；杀软误报不承诺为零，提供白名单引导文档 |
| 隐私 | MVP 无遥测，全本地优先；日志仅本地 |
| 可观测 | 统一日志规范（00 基石 §9.1），关键动作全覆盖 |
| 开源合规 | 第三方组件与工具 License 全量记录 + NOTICE 文件（00 基石 §8.6） |
| 离线能力 | 除版本比对数据源外，全部功能离线可用 |

## 6. 依赖与风险（PRD 视角）

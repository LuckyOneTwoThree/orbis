# Orbis MVP 功能清单

> **Feature Inventory / MVP 范围契约**
>
> - 上游：[00-产品基石](00-产品基石.md) v0.7（§5.2 双层 MVP：广度层 5 游戏 + 深度层鸣潮 L1 + 原神 L3 双标杆）
> - 下游：[02-MVP-PRD](02-MVP-PRD.md)（本清单每条功能 → 一个用户故事 + 验收标准）
> - 本文档只回答 **WHAT**（范围、优先级、依赖），不回答 HOW（交互、实现、视觉）

---

## 1. 使用规则

1. **清单外功能不得进入 PRD**——任何新增需求先回本清单评审，同步更新 00 基石 §5.2。
2. **P0 = MVP 发布门槛**（对应 00 基石 §12.4 A 组功能验收）。
3. **P1 = 顺延项**，资源紧张时按 §6 顺序后移，不阻塞发布。
4. 每条功能的「验收要点」是 PRD 验收标准（Given/When/Then）的种子，PRD 阶段展开。

## 2. 优先级定义

| 级别 | 含义 |
|------|------|
| P0 | MVP 必须，砍掉即不成立 |
| P1 | 计划内但可顺延至 V1.x / Phase 2+ |
| 不做 | MVP 明确排除（见 §4） |

## 4. 明确不做（MVP）

```
Mod Manager
抽卡 / 游戏数据工具
截图管理
账号切换（多账号）
社区 / 商城 / 社交
性能 Overlay / 性能中心
Tool Registry 外部工具市场（MVP 仅内置工具）
自研 CDN / Patch / 下载引擎
跨设备同步 / 云同步
```

对应 00 基石 §5.4，此处为清单级快照；冲突时以 00 基石为准。

**P1 顺延项**（属计划内顺延，非「不做」）：诊断中心、配置差异对比（00 基石 §5.2 P1 砍线第 4 条）。

## 5. 架构映射校验

| 域 | 架构模块（00 基石 §7） | 校验结果 |
|----|----------------------|----------|
| A 游戏管理 | Game Provider / Game Detector / Launcher Adapter | 覆盖 |
| B Enhancement | Backup Manager / Config Adapter / Launcher Adapter（解锁模式启动） | 覆盖 |
| C Tool 平台 | Tool Provider / Tool Manifest / Compatibility DB | 覆盖 |
| D 平台 UI | UI + Application Core（Logging） | 覆盖 |
| E 更新 | Update Adapter（只读检测） | 覆盖 |

结论：MVP 功能对 §7 架构无缺口要求，不需要为 MVP 新增架构层。

## 6. 建议开发顺序（关键路径）

```
① 地基：C1 Tool Manifest + D3 统一日志         ← 横切能力，最先
② 广度：A1 → A2/A3 → A4/A5 → A6/A7/A8        ← 依赖递进
③ 深度·鸣潮：C4 → B2/B3/B4 → B1 → B5/B6      ← 备份链路先于工具本身
④ 深度·原神：C2/C3（L3 授权流）→ B7 → B8      ← 可与 ③ 并行，不依赖备份链路
⑤ 界面整合：D1 / D2 / D4
⑥ 更新：E1（可与 ③④ 并行）
```

原则：**先横切后纵切；鸣潮闭环（B 域）依赖的通用能力（A8/C1）先于工具本身（B1）。**

## 4. 前端分层重构

引入 `src/api/` 作为**契约层**（UI 唯一依赖点）：

```
src/views/**     只消费 store（禁止 invoke / 路径拼接 / SQL / 哈希）
src/store/**     只调用 api，不做业务判定
src/api/         contract.ts（接口）+ types.ts（DTO）+ mock.ts + tauri.ts + index.ts
```

- `mock.ts` 是**行为对齐的参照实现**：真实实现兼容匹配（exact→prefix→none）、「需处理」判定式、
  执行流状态机与两层 detail、失败回滚、L3 门控；并**直接 import `data/` 的真实数据文件**
- `tauri.ts` 用映射类型 `ApiReturn<K>` 自动推断返回类型，转发与错误规整，无业务逻辑；
  参数名与契约严格一致，Core 落地时无需改动调用约定
- 删除 `src/mock/*`、`src/types/{game,enhancement,telemetry}.ts`（被取代）
- 删除前已建立仓外快照（`src/` 当时尚未入 git），避免不可逆丢失

- 三个脚本都做过**注入式反向测试**（故意写违规内容确认能拦住），不是空跑
- 断言脚本刻意只用 POSIX 字符类：`\s` / `\b` 是 GNU 扩展，在 macOS BSD grep 下会**静默不匹配**，
  让断言形同虚设（这是实际踩到的坑）

### 5.1 渲染测试为什么用 jsdom 而不是 `renderToString`

第一版用 `react-dom/server` 写，结果**整段测不出东西**，原因是两条：

1. zustand v4 的 `useStore` 把 `getInitialState()` 作为 `useSyncExternalStore` 的
   **server snapshot**，所以在 `renderToString` 下 hook 永远读到「store 创建时」的状态——
   实测 `getState().catalog.length === 5` 而 hook 读到 `0`，无论之前 setState 过什么
2. 空状态下多数视图会提前走「未找到游戏」分支，等于只测了错误路径

改为 jsdom + `react-dom/client`（真实客户端渲染路径，与浏览器一致）后才真正覆盖到数据渲染。
这个坑记录下来，避免以后有人再写一遍 SSR 版本。

已实现的平台无关切片，含表驱动用例：

| 模块 | crate | 覆盖 |

| `attention` | core | 五类需处理原因、工具未启用仍需关注、Running 不算需处理、`version_unknown` 与 `update_available` 正交、去重 |

| `manifest` | tools | Manifest 解析与验证、`config_modify` 必须 `backup_required`（规则 5 的最后一道闸）、`upstream` 必须署名、`unlocker` 必须指向资产、重复 id 冲突、**单个损坏只让该工具不可见（02 C1）** |
| `assets` | tools | 资产清单解析、SHA256 形态校验、平台白名单、**`artifacts` 为空是合法降级态而非错误（Q1 未定稿）** |
| `lib`（`cross_check`） | tools | seed ↔ manifest ↔ assets 跨文件一致性（缺失条目 / 游戏标识不一致 / 资产缺失 / 资产未配置），并区分「缺陷」与「须知」 |

> **一处刻意的架构修正**：最初把 `GameId` 写成含 5 款游戏的闭集枚举，被自己的架构断言拦下 ——
> 那等于把游戏清单硬编码进 Core，使「新增游戏不修改 Core」不成立。
> 现改为不透明 slug 校验类型，**游戏清单归 `orbis-providers` 的编译期 catalog**。
> 代价是无法对游戏做穷尽匹配，换来的是规则 1 真正成立。

> **数据加载的落点（2026-09-20 补）**：三份内置数据按「拥有者加载自己的数据」分派 ——
> 种子表归 `orbis-core`（兼容引擎的数据），Manifest 与资产清单归 `orbis-tools`（04 §4.1 的分工）。
> 均用 `include_str!` 烘进二进制（04 §6.2）。`include_str!` **不违反「Core 零游戏知识」**：
> 游戏标识在数据文件里，不在 Core 的源码中，`check-architecture.sh` 的 [1] 已验证通过。
> 三个加载器一律**返回部分成功而非 `Result`**（`ManifestSet` / `SeedTable` / `AssetCatalog`），
> 目的是让「静默降级」在类型层面写不出来 —— 失败原因必须经 `BuiltinData::degradations` 交回调用方落日志。
